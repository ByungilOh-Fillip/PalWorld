# 공통 인터페이스

인터페이스는 플레이어, 팰, 월드 시스템의 직접 참조를 줄이기 위한 최소 경계다.
실제 호출자가 생기는 시점에 필요한 함수만 추가한다.

## `IPW_WorldStateProvider`

목표: 스폰, 온도, 작업 건물이 구체 `GameState`에 직접 의존하지 않게 한다.

구현 항목:

- [ ] 현재 일자 조회
- [ ] 현재 시간 조회
- [ ] 낮/밤 여부 조회
- [ ] 현재 월드 온도 보정값 조회

완료 기준:

- [ ] 스포너와 온도 시스템이 `APW_WorldGameState` 구체 타입 없이 월드 상태를 읽을 수 있음

## `IPW_GameplayTagStatusTarget`

목표: 온도 시스템이 플레이어/팰 구현체를 직접 몰라도 상태 적용 요청을 보낼 수 있게 한다.

구현 항목:

- [ ] 상태 태그 적용 요청 함수
- [ ] 상태 태그 해제 요청 함수
- [ ] 상태 태그 보유 여부 조회 함수

완료 기준:

- [ ] 온도 시스템이 `Status.Explo.Cold`, `Status.Explo.Heat` 적용/해제를 요청할 수 있음
- [ ] 실제 상태 효과 처리는 플레이어/팰 파트가 담당함

## `IPW_WorkPerformer`

목표: 작업 건물이 팰 클래스를 직접 참조하지 않고 작업 가능 여부를 판단한다.

구현 항목:

- [ ] 보유 작업 태그 조회
- [ ] 작업 레벨 조회
- [ ] 현재 상태 태그 조회
- [ ] 작업 시작 알림
- [ ] 작업 중단 알림
- [ ] 작업 완료 알림

완료 기준:

- [ ] 작업 건물이 팰 구체 클래스 없이 작업 배정 가능 여부를 판단할 수 있음

## `IPW_WorkTarget`

목표: 팰 파트가 작업 건물과 월드 자원을 같은 방식으로 탐색할 수 있게 한다.

구현 항목:

- [ ] 요구 작업 태그 조회
- [ ] 작업 가능 여부 조회
- [ ] 작업 슬롯 예약
- [ ] 작업 슬롯 해제
- [ ] 작업 결과 전달 hook

완료 기준:

- [ ] 팰 파트가 건물/자원 구분 없이 작업 대상을 검색하고 예약할 수 있음
