# 2026-06-28_v1 구현 계획

## 구현 목표

첫 구현 범위는 `World Time + Temperature v1`이다.
서버 권한 월드 시간과 온도 볼륨 기반 탐험 상태 태그 요청을 구현한다.

## 서버-클라이언트 통신 구조

```text
Server WorldSubsystem
    권한 로직 실행
    ↓
Server GameState / Actor 상태 변경
    ↓
Replication
    ↓
Client OnRep / replicated actor state
```

- 시간은 Client RPC 없이 `GameState` Replication으로 동기화한다.
- 온도는 서버에서 판정하고 상태 태그 적용/해제 요청만 보낸다.
- 실제 상태 효과와 UI 표시는 플레이어/팰/상태 시스템이 담당한다.

## 책임 분리

| 위치 | 책임 |
|---|---|
| `APW_WorldGameState` | 복제될 월드 시간 상태 |
| `UPW_WorldTimeSubsystem` | 서버 시간 진행 |
| `APW_TemperatureVolume` | 배치형 온도 판정 영역 |
| Interface | 플레이어/팰 파트와 직접 참조 없이 연결 |

## 구현 항목

1. `GameplayTags` 모듈 의존성 추가
2. `APW_GameModeBase` 추가
3. `APW_WorldGameState` 추가
4. `UPW_WorldTimeSubsystem` 추가
5. `IPW_WorldStateProvider` 추가
6. `IPW_GameplayTagStatusTarget` 추가
7. `Status.Explo.Cold`, `Status.Explo.Heat` Native GameplayTag 등록
8. `APW_TemperatureVolume` 추가
9. `DefaultEngine.ini`에 기본 GameMode 연결

## 테스트 기준

- `PalWorldEditor` 빌드 성공
- 서버에서 시간이 증가
- 클라이언트가 `CurrentDay`, `CurrentTimeOfDay`를 복제받음
- 낮/밤 판정이 서버와 클라이언트에서 동일
- 온도 볼륨 진입 시 Cold/Heat 태그 적용 요청 발생
- 온도 볼륨 이탈 시 Cold/Heat 태그 해제 요청 발생

## 제외 범위와 가정

- 날씨, 야생 팰 스폰, 작업 건물은 이번 구현에서 제외한다.
- 상태 효과 자체는 플레이어/팰/상태 시스템이 담당한다.
- 온도 볼륨 중첩 처리는 v1에서 제외한다.
- 하루 길이는 기본 `1200초`, 낮 시작은 `06:00`, 밤 시작은 `18:00`으로 둔다.
